# Commit Current Changes

## Phase 1: Assess Changes

1. **Check current state:**
   ```bash
   git status
   git diff --stat
   ```

2. **Review what will be committed:**
   - Unstaged changes: `git diff`
   - Staged changes: `git diff --cached`

3. **Identify logical groupings** (if multiple unrelated changes exist):
   - Group by feature/fix (e.g., all auth-related files together)
   - Group by layer (e.g., all API changes, then all UI changes)
   - When in doubt, ask user how to split

---

## Phase 2: Comment Quality Check (MANDATORY)

**Scan for unprofessional comments before committing**

1. **Search for comments that are not helpful for future developers, and instead focus on actions taken by the chatbot or temporary notes.**


2. **Review flagged comments:**
   - For each match, examine context in the actual file
   - Determine if it violates comment standards (see `.claude/rules/code-comment-standards.md`)

3. **Fix problematic comments:**
   - **Remove** commit-style, obvious, or casual comments
   - **Enhance** comments to explain WHY, not WHAT
   - **Replace** TODOs with tickets or specific removal criteria
   - If unsure, ask user for guidance

4. **Re-stage fixed files:**
   ```bash
   git add <fixed-files>
   ```

---

## Phase 3: Stage Files

**Option A: Single logical change**
- Stage all related files: `git add <files>`

**Option B: Multiple unrelated changes**
- Create separate commits for each logical group
- Stage first group, commit, then repeat

---

## Phase 4: Commit

1. **Check recent commit style:**
   ```bash
   git log --oneline -5
   ```

2. **Write commit message:**
   - Max 2 lines (subject + optional body)
   - Follow project's commit convention (check CLAUDE.md or recent commits)
   - No AI attribution ("Generated by Claude", etc.)

3. **Execute commit:**
   ```bash
   git commit -m "subject line" -m "optional body"
   ```
   - **Never use `--no-verify`**

---

## Phase 5: Handle Failures

If commit fails due to pre-commit hooks:

1. **Read the error message carefully**
2. **Fix the issues** (linting, formatting, tests)
3. **Re-stage fixed files**
4. **Retry commit**

If issues cannot be fixed:
- Report the specific error to user
- **Do not bypass with --no-verify**
- Wait for user guidance

---

## Constraints

- **Phase 2 is MANDATORY**: Always check for bad comments
- Commit messages: max 2 lines
- No `--no-verify` flag
- No AI attribution
- Fix hook failures, don't skip them
- Ask user if unsure about grouping or comment quality
